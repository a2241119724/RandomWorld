# RandomWorld 项目业务架构分析报告

> 生成日期: 2026-08-09  
> 分支: feature/dev-0.1.3  
> 项目: 2D 像素风生存/殖民地建设多人游戏

---

## 一、项目概述

**RandomWorld** 是一款基于 Unity 的 **2D 像素风生存/殖民地建设多人游戏**，使用 **Photon PUN 2** 实现网络多人同步，内置基于本地 LLM (Qwen2.5-0.5B) 的 AI NPC 对话系统。代码命名空间为 `LAB2D`，整体采用 **洁净架构 (Clean Architecture) + 领域驱动设计 (DDD)** 模式，通过 **ServiceLocator** 实现轻量级依赖注入。

  GlobalInit (BeforeSceneLoad)
    └→ RegisterSafeServices: Singleton<T> 和 ASingletonSaveData<T> 自创建服务
  GlobalInit.Awake()
    └→ RegisterServices: MonoBehaviour 服务 + 适配器注册

        └→ ServiceLocator.Register<IMapWalkabilityQuery>(mapAdapter)

    └→ BuildInitializableList: 构建 IInitializable 有序列表
  GlobalInit.Start()
    └→ 依次执行 IInitializable.Initialize()
    └→ GlobalPanelInitializer.InitializeAll()
  GlobalInit.Update()
    └→ 依次执行 ITickable.Tick(dt)

## 八、关键架构特征总结

| 特征 | 实现方式 |
|------|----------|
| **分层架构** | 基础设施 → 核心引擎 → 领域 → 适配器 → 表现层，严格的单向依赖 |
| **领域驱动设计** | Domain/ 层零 UnityEngine 引用 (74 文件)，纯 C# 无状态 RuleService |
| **依赖注入** | ServiceLocator 静态 DI 容器 — Register/Get/TryGet/GetAll，约 44 个注册 |
| **依赖反转** | Domain/Common/ 中 20 个文件定义接口 (IGameTime, IMapWalkabilityQuery, IEnemySpawnService...) |
| **启动流程** | GlobalInit: BeforeSceneLoad 安全注册 → Awake 适配器注册 → Start 初始化 → Update Tick |
| **适配器模式** | UnityAdapter/ 13 文件将 Unity 特有类型转换为领域值对象 |
| **EventBus** | 集中式发布/订阅解耦 (PlayerMoved, Damaged, WaveChanged, WorkerTask, InventoryGridChanged...) |
| **命令模式** | IGameCommand (PlayerMoveCommand, PlayerAttackCommand, ActivateSkillCommand) |
| **状态机** | 泛型 `CharacterStateManager<CS, CST, C>` — Enemy 4-5 状态，Worker 6 状态 |
| **对象池** | A* 寻路的 SpendPool、FloatingText 对象池 (30-60 实例) |
| **快照模式** | WorkerAgentSnapshot / WorkerTaskSnapshot 隔离领域与 Unity 对象 |
| **Provider 委托** | Worker 系统通过静态委托注入 Log/Network/Item/ColonyCommand 依赖 |
| **多线程寻路** | A* 在后台线程运行，Semaphore 控制并发，WalkabilityCache 无锁读取 |
| **网络同步** | Photon PUN 2 — RPC / IPunObservable / PhotonView，NetworkViewAdapters 适配层 |
| **存档系统** | ArchiveManager 反射发现 ASaveData 子类，二进制序列化，最多 10 个槽位 |
| **MVC 框架** | 泛型 MVC 基类 (6 个) → Backpack(背包) / Build(建造) 两个具体模块 (各 6 文件) |
| **LLM 对话** | 本地 llama-server + SSE 流式输出 + RAG 知识检索 + 短期/长期记忆 |
| **HUD 热键** | F1-F8 功能键切换各 HUD 面板 (技能/成就/天气/工人状态/补给/任务队列/指挥中心)，F9 房间列表 |
| **单元测试** | Editor/Tests/Domain/ 下 38+ 测试文件，覆盖所有领域服务 |
| **建造韧性** | 位置预注册 + 建造者名称参数 → 任务恢复；最多 3 次卡死重试（碰撞 Bug 保护） |
| **日志工厂** | GameLoggerFactory 统一获取 IGameLogger，替换所有硬编码 Debug.Log（31 文件迁移） |

### 9.4 Inventory/ — 库存管理 (9 文件)

完整的领域库存系统，InventoryService 作为门面统一对外，内部委托给子服务。

| 类 | 职责 |
|-----|------|
| `InventoryService` | **库存门面** — 管理 InventoryGrid，委托子服务处理堆叠/预留，通过可注入 `eventPublisher` 发布事件 |
| `InventoryGrid` | 网格管理 — cellsByPos 字典 + positionsById/positionsByType 双索引，支持 AddCell/RemoveCell/AddItem/TakeItem/FindBestPositionForItem |
| `InventoryCell` | 可变格子模型 — 包装 ResourceStack，提供 Add/Take/Clear/CanAdd 操作 |
| `ResourceStack` | 不可变值对象 (struct) — ItemId + Count + Capacity，Take/Add 返回新实例 |
| `InventoryStackingService` | 堆叠容量计算 (cellCapacity - current - reserved)，可用性检查 |
| `InventoryFoodReservationService` | 食物预留 (工人饥饿值 → 所需食物数) |
| `InventoryTakeReservationService` | 并发取出预留，防止双重领取 |
| `InventoryGridChangedEvent` | **新版事件** — 结构化数据: ChangeType / Position / ItemId / Count / Capacity / ManagerName |
| `InventoryCellChangedEvent` | **[已废弃]** 旧版事件，保留向后兼容，新订阅者应使用 InventoryGridChangedEvent |

**关键设计:**
- 所有位置使用 `GameGridPosition` (Domain 坐标)，不依赖 Unity Vector3
- `eventPublisher` 默认为 `EventBus.Instance.PublishInternal`，支持测试注入
- `itemTypeResolver` 委托实现 ID→Type 转换，由 UnityItemDefinitionAdapter 注入

## 十二、设计模式应用汇总

| 模式 | 应用位置 | 说明 |
|------|----------|------|
| **洁净架构** | 全局 | Domain 层零 Unity 依赖，通过接口反转依赖方向 |
| **领域驱动设计** | Domain/ | 8 个子域 (74 文件)，无状态 RuleService，值对象 |
| **依赖注入** | Core/ GlobalInit | ServiceLocator 静态 DI 容器 + 显式注册 + Provider 委托 |
| **适配器模式** | UnityAdapter/ | 13 个适配器桥接 Unity 类型与领域接口 |
| **命令模式** | Domain/Common/ | IGameCommand → PlayerMove/Attack/Skill 命令 |
| **事件驱动** | Domain/Common/ | EventBus + IGameEvent 发布/订阅解耦 |
| **状态机模式** | Character/ | 泛型 `CharacterStateManager<CS, CST, C>` |
| **工厂模式** | Character/ | CharacterCreator<T> 模板方法 |
| **门面模式** | Domain/Inventory/ | InventoryService 封装 Grid+Stacking+Reservation 子服务 |
| **管理器/注册表** | Manager/ Gameplay/ | 单例管理器模式 (CharacterManager, WaveManager...) |
| **MVC 模式** | MVC/ | 泛型 MVC 基类 (6 个) → Backpack / Build 模块 (各 6 文件) |
| **对象池** | Core/Seek/ UI/ | SpendPool (A*), FloatingText 对象池 |

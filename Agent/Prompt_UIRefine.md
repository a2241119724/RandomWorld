# Unity UI 视觉优化与美学精炼 Prompt

请基于 `./Agent` 中的 Agent 体系，对项目中已有的 UI 进行一轮系统的视觉优化与美学精炼。

> 扫描 Game.unity 场景和 ResourcesLocal/Prefabs 下的 UI → 识别视觉问题 → 生成优化任务卡 → 执行美化 → 验证记录 → 更新状态

---

## 1. 总目标

- 对 `Scenes/Game.unity` 和 `Assets/ResourcesLocal/Prefabs/` 下所有 UI 进行全面视觉审计。
- 自动识别字体、颜色、尺寸、间距、对齐、层级、视觉层次等美学问题。
- 对每个可优化点执行低风险、可回滚的视觉调整。
- 一次只优化一个 UI 模块/面板/区域，确保可控性。
- 所有修改必须有回滚方案，优先保证不破坏功能绑定和引用。

## 2. 核心设计原则

### 2.1 字体与可读性

- **字号层级**：标题 > 副标题 > 正文 > 辅助文字，形成清晰的 3-4 级字号梯度（如 28/22/16/12 或项目已有风格）。
- **行间距**：正文行间距不低于字号的 1.3 倍，确保阅读舒适。
- **字体统一**：同一面板内不超过 2 种字体，优先复用 TextMesh Pro 全局字体资源。
- **对比度**：文字颜色与背景必须有足够对比度，浅色背景用深色文字，深色背景用浅色文字。
- **避免挤压**：文字区域留足 padding，防止文字与边框/图标/边缘紧贴。

### 2.2 颜色体系

- **语义色一致**：血量为红色系、护盾/魔法为蓝色系、金币/奖励为金色/黄色系、警告/危险为橙红系、成功/正面为绿色系、信息/提示为蓝灰或白色系。
- **不超 4 个主色**：一个面板内的核心颜色（不含黑/白/灰）控制在 3-4 个以内。
- **透明度层次**：背景遮罩 50-70% 透明度、面板背景 80-95%、前景内容 100%，形成前景 > 面板 > 遮罩的视觉深度。
- **按钮状态色**：Normal / Hover / Pressed / Disabled 四种状态颜色有明确差异。
- **统一调色板**：同场景中的 UI 共享一组语义色，不出现"这个绿色不同于那个绿色"的微小偏差。

### 2.3 尺寸与比例

- **黄金比例偏好**：面板宽高比优先接近 16:10 / 16:9 / 4:3 / 1:1 等常见比例，避免过于狭长或扁平无规则。
- **按钮最小尺寸**：可点击按钮不小于 44x44 像素（移动端标准），PC 端不小于 32x24。
- **内容决定大小**：容器尺寸应适配内容，不出现大片空白也不出现内容被截断。
- **比例一致性**：同类元素（如背包格子、技能图标、物品图标）保持统一尺寸。

### 2.4 布局与对齐

- **网格对齐**：列表、背包、技能栏等重复元素使用 GridLayoutGroup 时确保 Cell Size 和 Spacing 统一。
- **边距统一**：同一面板的左右边距一致、上下边距一致，不出现左边距 10 右边距 15 的不对称。
- **对齐方式**：标题居中或左对齐，数字/数值类信息优先右对齐或居中，文本优先左对齐。
- **锚点正确**：UI 根节点锚点覆盖预期显示区域，子元素锚点合理（如关闭按钮固定右上角、确认按钮固定底部居中）。
- **层次缩进**：子级内容相对父级有明确缩进（通常 10-20px），形成视觉层级。

### 2.5 视觉层次

- **前景/背景分离**：重要信息（血量、分数、倒计时）用更大字号 + 更亮颜色 + 更高层级；装饰性元素降低透明度或缩小。
- **焦点引导**：用户视线应有自然落点——默认打开面板后第一个关注点应是核心内容，而非装饰或次要按钮。
- **留白**：元素之间保留足够间距（默认 6-12px），避免拥挤；分组间距 > 元素间距（如 16-20px）。
- **阴影/描边**：重要文字或图标可加柔和阴影或描边以提升可读性，但不过度使用。

## 3. 审计范围与优先级

### 3.1 必审路径

| 路径 | 审计重点 |
|---|---|
| `Scenes/Game.unity` 中的 Canvas 子节点 | 所有 Panel、HUD、Button、Text、Image、ScrollView |
| `ResourcesLocal/Prefabs/` 中所有 `.prefab` | UI 组件的 RectTransform、Text/TMP、Image、LayoutGroup、Button |
| `ResourcesLocal/Prefabs/ItemBox/` | 物品格、按钮项、聊天项等列表项样式统一性 |
| `ResourcesLocal/Prefabs/Character/` | 角色/玩家/工人相关 UI 预制体 |

### 3.2 审计优先级

1. **P0 — 游戏核心 HUD**：血量、状态、分数、波次、技能冷却等始终可见的 UI。
2. **P1 — 高频交互面板**：背包、建造菜单、物品信息、确认弹窗、结算面板。
3. **P2 — 辅助面板**：聊天、任务列表、成就、设置、图鉴等。
4. **P3 — 调试/开发者面板**：仅在开发阶段可见的 UI。

## 4. 只读扫描范围

扫描项目上下文，重点检查：

- `Scenes/Game.unity` 的真实路径及现有 UI 层级、Canvas 结构、EventSystem 配置。
- `ResourcesLocal/Prefabs/` 下所有 `.prefab` 的 RectTransform、TextMeshProUGUI、Image、Button、LayoutGroup 组件参数。
- 现有 UI 中的字号分布：最小字号、最大字号、常见字号，评估是否形成清晰层级。
- 现有 UI 中的颜色分布：提取所有 Color/RGBA 值，识别语义不一致的颜色使用。
- 现有 UI 中的布局问题：重叠、挤压、对齐不均、间距不统一、锚点异常。
- `Scripts/2D/UI` 中已有 UI 控制器、Panel 基类、HUD 管理器的绑定方式——调整视觉时不得破坏代码绑定。
- `Scripts/2D/Constant` 中已有 UI 相关常量（颜色、字号、节点名、路径）。
- 历史任务卡中涉及 UI 修改的记录。

## 5. 执行步骤

### 5.1 读取 Agent 体系文件

读取 `Agent/README.md`、`Agent/Docs/SkillCatalog.md`、`Agent/Config/agent_registry.json`、`Agent/Config/task_router.json`。

### 5.2 扫描 UI 资产

- 搜索 `Game.unity` 真实路径。
- 递归列出 `ResourcesLocal/Prefabs/` 下所有 `.prefab`。
- 对每个 UI Prefab / Scene UI 节点，提取关键视觉参数：字号、颜色、尺寸、间距、锚点、排序层级。

### 5.3 生成视觉审计报告

报告写入 `Agent/Reports/<今天日期>/uirefine_audit_<HHmmss>.md`，包含：

- **字号审计**：列出所有使用的字号及其分布，标记过大/过小/层级混乱项。
- **颜色审计**：列出所有使用的颜色值（含 Alpha），标记语义不一致、对比度不足、色相偏离项。
- **尺寸审计**：列出所有 UI 元素的尺寸，标记比例异常、过小点击区、过大占位项。
- **布局审计**：标记重叠、挤压、边距不统一、对齐偏差、锚点异常项。
- **视觉层次审计**：标记主次不清、焦点模糊、留白缺失项。
- **优化建议列表**：每个建议含路径、节点名、问题描述、优化方向、风险等级、预估成本。

### 5.4 自动选择优化目标

从审计报告中按以下优先级选择：

1. 低风险、高视觉收益（如调整字号、颜色、间距——不涉及结构变化）。
2. 中风险、高视觉收益（如调整布局、锚点——涉及 RectTransform 参数调整）。
3. 高风险项目跳过（如需要修改 Prefab 变体嵌套结构、需要修改代码绑定逻辑）。

一次只选一个 UI 模块/面板/区域进行优化。

### 5.5 生成任务卡

任务卡路径：`Agent/Reports/<今天日期>/uirefine_<模块名>/task_uirefine_<模块名>.md`

任务卡必须包含：
- 审计来源（审计报告路径）。
- 优化目标 UI 模块/面板/区域。
- 当前视觉问题描述（配具体参数值）。
- 优化方案（目标字号/颜色/尺寸/间距/对齐值）。
- 影响路径：涉及的 Scene 节点路径或 Prefab 路径。
- 不应修改项：代码绑定、功能引用、脚本挂载、已有关键节点名。
- 回滚方案：如何精确撤销修改。
- 使用的工具类/枚举/常量。

### 5.6 执行视觉优化

- **Game.unity 中的 UI**：直接修改 YAML 中的 RectTransform、Text、Image、LayoutGroup 等组件参数。
- **ResourcesLocal/Prefabs 中的 UI**：修改 Prefab YAML 中的对应组件参数，保留 `.meta`。
- **不修改**：节点名称（除非命名明显混乱且不影响代码绑定）、脚本挂载、事件绑定、动画关键帧。
- **可修改**：fontSize、color、sizeDelta、anchoredPosition、spacing、padding、alpha、pivot、anchorMin/Max。

### 5.7 验证

验证记录写入 `Agent/Reports/<今天日期>/uirefine_<模块名>/validation_uirefine_<模块名>.md`。

验证内容：
- 编译通过。
- Game.unity 能正常打开场景。
- Prefab 引用完整（`.meta` 存在且 GUID 正确）。
- 修改后的字号形成清晰层级（至少能区分标题/正文/辅助文字）。
- 修改后的颜色语义一致（同类型信息使用一致颜色）。
- 修改后的布局无重叠、无截断、无异常空白。
- 代码绑定未受影响（检查脚本中的 `GetComponent`、`Transform.Find`、`[SerializeField]` 引用路径）。

### 5.8 更新结果

在任务卡结果区写入：
- 优化前后的视觉参数对比（字号/颜色/尺寸/间距的具体变化）。
- 修改文件列表。
- 验证结果。
- 剩余视觉问题（本轮未处理的）。

### 5.9 更新审计报告

将已处理项在审计报告中标记为 `[DONE]`，写明任务卡路径。

## 6. 约束与禁忌

- 不向我提问，不等待我确认。
- 所有修改必须低风险、可回滚。
- 不修改节点名称，除非确认无代码引用且命名严重混乱。
- 不修改脚本挂载、事件绑定、Prefab 变体嵌套结构。
- 不新增或删除 UI 节点（仅调整已有节点的视觉参数）。
- 不修改动画、Animator、AnimationClip。
- 所有生成注释使用中文。
- 不触及其他 Prompt（Feature / Efficiency / Ambitious）的职责范围——本次只做视觉精炼，不新增业务功能。
- 若无法确认某参数的安全修改范围，跳过并记录原因。

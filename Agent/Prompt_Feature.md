请基于 ./Agent 中的 Agent 体系，自动完成一次“分析现有游戏业务 -> 发现可扩展的新功能机会 -> 生成候选功能列表 -> 选择最适合的候选 -> 生成任务卡 -> 开发新功能 -> 验证记录 -> 更新候选完成状态”的完整流程。

重要要求：
- 不要向我提问。
- 不要等待我确认。
- 如果遇到需要人工确认的高风险候选，请自动跳过它，选择下一个低风险或中风险候选。
- 一次只开发一个游戏业务相关的新功能。
- 本次目标不是只做代码扫描工具，而是优先生成并开发“能增强游戏体验、玩法闭环、UI 交互、玩家反馈、系统完整性”的业务功能。
- 每次任务必须在 Agent/Reports/<今天日期>/ 下创建独立任务文件夹，所有本次任务相关输出都必须放入该文件夹中，避免和同一天其他任务混在一起。

独立任务文件夹命名格式建议为：
- Agent/Reports/<今天日期>/<候选ID>_<功能名安全短名>/

如果在选择候选前无法确定候选ID，则先使用：
- Agent/Reports/<今天日期>/run_<HHmmss>/

选定候选后，可继续使用该目录，也可重命名为：
- <候选ID>_<功能名安全短名>

同一天多次执行时，不得覆盖已有任务目录；如目录已存在，自动追加时间戳或序号。

功能选择原则：
- 优先选择低风险、高价值、边界清晰、能在一次任务中完成的游戏业务功能。
- 优先考虑以下类型的新功能：
  - 玩家体验增强功能，例如新手提示、操作反馈、状态提示、交互引导。
  - UI 业务功能，例如背包提示、任务面板、道具说明、结算展示、设置入口。
  - 玩法辅助功能，例如简单奖励逻辑、冷却提示、进度显示、成就提示、任务状态展示。
  - 内容展示功能，例如角色属性展示、关卡信息展示、资源收集进度展示。
  - 低侵入业务闭环，例如已有数据的 UI 展示、已有按钮的行为补全、已有系统的状态反馈。
  - Editor 辅助生成功能，用于帮助后续快速创建游戏业务配置、模板或预览内容。
- 可以开发只读分析或报告工具，但只有在没有合适的低/中风险业务功能时才优先选择。
- 不要优先选择纯技术型工具，除非它能直接服务于游戏业务功能开发。
- 不要优先选择会直接修改 Scene、Prefab、ScriptableObject、StreamingAssets、存档结构、Photon 同步或 AssetBundle 的功能。
- 如果候选功能必须直接修改 Scene、Prefab、ScriptableObject、StreamingAssets、存档、Photon 或 AssetBundle，且无法通过安全的代码增量方式完成，则跳过。
- 如果所有候选都属于高风险，则只实现一个不改业务资产的只读业务分析/报告工具。

候选生成要求：
- 生成候选功能列表时，必须为每个候选分配唯一编号和完成状态，便于后续判断该候选是否已经处理完成。
- 候选必须面向“游戏业务功能”，不能只罗列代码质量优化、重构、格式化、扫描类任务。
- 每个候选都要说明它来自哪个业务缺口，例如：
  - 有 UI 入口但没有业务行为。
  - 有数据字段但没有展示。
  - 有资源但没有使用。
  - 有脚本逻辑但没有玩家反馈。
  - 有配置但没有验证或展示。
  - 有 TODO/FIXME 指向未完成玩法。
  - 有系统模块但缺少完整闭环。
- 完成功能实现与验证后，必须回写本次任务目录中的 feature_discovery.md 中对应候选的状态标记。
- 扫描历史记录时，必须递归检查 Agent/Reports/ 下所有日期目录及其子任务目录中的 feature_discovery.md、task_*.md 和 validation_*.md，避免重复实现已经 `[DONE]` 的候选。

候选状态规则：
- `[TODO]`：待处理，尚未实现。
- `[DONE]`：已完成，已实现并完成可行验证。
- `[SKIPPED]`：已跳过，通常因为高风险、边界不清晰、需要人工确认或涉及敏感资源修改。
- `[BLOCKED]`：受阻，已分析但因缺少环境、依赖、权限或无法验证而未完成。
- `[PARTIAL]`：部分完成，已实现部分能力，但仍存在明确未完成项。

|---|---|---|---|---|---|---|---|---|---|---|
